# 網站造訪與功能統計

目前使用 GoatCounter 站台 `yuhsin`，設定在 `site/usage-config.js`。
站台代碼是公開設定，不是登入信箱，也不是 API 金鑰。登入資訊不放入網站。

網站頁尾的「瀏覽人數」讀取 `/site-visit` 自啟用日 2026-10-27 起的累計造訪數；各功能頁的瀏覽與事件另外記錄，避免把同一個人切換功能的次數加總成人數。
這是累計造訪人次，不是永久不重複的人數。本機預覽不發送統計。

在 GoatCounter 的 Settings 勾選「Allow adding visitor counts on your website」即可開放公開數字；Dashboard 可維持 Only logged in users。
公開計數 API 會快取，數字不一定即時更新；新站尚未收到資料或讀取失敗時顯示「統計更新中」，不以假造的 0 取代。
官方說明：https://www.goatcounter.com/help/visitor-counter

## 學群探索施測次數（2026-10-28 起）

在 [GoatCounter 後台](https://yuhsin.goatcounter.com/) 選擇相同日期區間，查看以下事件：

| 事件 | 意義 |
| --- | --- |
| `curiosity-assessment-start` | 開始一份全新探索，重複按開始只記一次 |
| `curiosity-assessment-complete` | 首次完成基本測驗並產生結果，每份作答記一次 |
| `curiosity-retest-complete` | 完成一批「重新測驗」題目，每批記一次 |
| `curiosity-deep-complete` | 完成「深入探索」，每份作答記一次 |

上述事件用 `no_session: true`，同一瀏覽器完成多份新測驗也會逐次計入。已送出階段標記與原本進度一起保存在瀏覽器；重新整理、重看結果或調整學科不重複計次。新版啟用前已完成的舊存檔不回補，過去次數無法還原。`curiosity-result` 僅代表開啟結果頁，不用來當作完成施測次數。

報告建議分別呈現「完成基本測驗人次」「重新測驗完成批次」「深入探索完成次數」；三者相加只可稱為完成活動次數，不能稱為不重複受測人數。這些匿名統計不集中保存個人答案、學科表現、姓名或完整結果。使用者自己的作答仍只保留最新一份於本機瀏覽器。統計可能受阻擋追蹤、網路中斷、清除儲存或同時開啟多個分頁影響，屬使用量估計，不是考試稽核紀錄。

建議每月保留相同口徑的後台報表，註明起訖日期、統計起用日及指標定義。開始與完成可能跨月，直接相除只能作為期間參考，不能當作嚴格的同批受測者完成率。

## 後續結果保存與信效度研究建議

先累積匿名使用次數即可佐證推廣觸及與使用情形。高使用量不能直接證明測驗信度或效度。

若要集中保留每次結果，需要增加伺服器或受控資料庫；GitHub Pages 本身只提供靜態網頁。建議分成兩個階段：

1. 使用成果：每月完成基本測驗人次、重新測驗與深入探索次數，搭配自願填寫的「是否幫助認識學群」回饋。
2. 研究資料：在明確說明研究用途與保存期間、取得適當同意後，保留可配對的研究代碼、題庫與計分版本、實際題號、逐題答案、完成時間及結果。研究資料需放在有權限控管的資料庫，不得提交到公開儲存庫。

本工具每次只從十八學群各抽一題，深入探索與重新測驗又會增加不同題目；不能只用最後推薦學群，或把十八學群視為同一量尺，直接計算整份問卷的 Cronbach's α。應先定義欲測量構念與使用目的，再請輔導或測驗專家審題、設計固定研究題組、安排例如間隔 2–4 週的重測，並比較同一構念的既有量表或其他外部證據。具體樣本數和分析方式需依研究設計規劃；學生滿意度可作為有用性回饋，不能單獨作為效度證明。

參考：[GoatCounter 事件](https://www.goatcounter.com/help/js)、[教育與心理測驗標準](https://www.testingstandards.net/)。

## TOP 10 學類

目前十個學類由人工設定，並非統計排名。選取學類時，以 `placement-category-<英文代碼>` 記錄匿名功能事件。
可在累積資料後，以最近 30 天的學類選取次數產生排名；未來若需要去重，應以統計服務提供的造訪資料計算，而不是在瀏覽器建立個人識別碼。
如要自動更新預設清單，可由伺服器端或 GitHub Actions 讀取統計後產生公開排名檔；API 金鑰應只放在執行環境的 Secret，不可寫入前端。
