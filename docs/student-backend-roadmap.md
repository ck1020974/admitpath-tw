# 正式登入與私人後台

更新：2026-10-29。單一學校，學生預設帳號與密碼皆為原始學號，不強制首次改密碼。

## 現在的架構

公開網站保留在 GitHub Pages。學生在既有彈出視窗輸入學號與密碼，Supabase Edge Function 將學號對應至內部驗證帳號，再由 Supabase Auth 核對密碼。學生不需提供信箱；內部識別信箱不寄信、不作聯絡用途。

瀏覽器只取得公開 anon 金鑰與自己的工作階段，沒有管理金鑰、名單檔或密碼清單。跨網站請求使用 bearer token，避免依賴第三方 cookie；工作階段僅保留在當前分頁的 sessionStorage，登入密碼不保存。每次恢復登入都向 Auth 與學生資料表重新核對身分和啟用狀態，沒有資料列的 Auth 帳號不能成為本站學生。

目前使用 legacy anon 公開 JWT 配合 Edge Function 的 legacy JWT gateway 驗證。該金鑰只能在權限規則內存取資料，不等於管理金鑰。若未來改用新 publishable key，需連同 Edge gateway 與函式內驗證方式一起調整，不能只替換字串。

學生名單的 `teaching_group`（上課班級）與 `original_class`、`original_seat_number`（原班級與座號）各自保存。10A 不覆蓋原班級，後台可依上課組別或原班級分別篩選。

## 已建立的資料底座

| 資料表 | 用途 | 學生權限 |
| --- | --- | --- |
| students | 身分、上課班級、原班級、啟用狀態 | 讀取自己的公開個人欄位，不能改學號、角色或登入映射 |
| teacher_access | 教師、學校／組別範圍、管理與匯出權限 | 不可讀取他人的授權或自行取得教師身分 |
| tracking_items | 校系追蹤、加入／移除時間、版本 | 讀取自己的清單，經驗證端點新增／移除 |
| assessment_attempts | 每次全新測驗、版本、施測時班級與來源 | 讀取自己的施測資料；開始及完成經受控端點保存 |
| assessment_results | 初次／補題／深入／修訂結果快照 | 讀取自己的歷次成果，後端重新計分後保存 |
| counseling_notes | 教師私人晤談備註與追蹤日期 | 無讀取權限 |

所有資料表均啟用 Row Level Security，匿名角色沒有學生資料讀取權限。瀏覽器對歷程表仍只有受限讀取權，所有寫入經 `student-records` Edge Function：由 Auth 驗證身分、讀取啟用學生資料，再呼叫只授權 service_role 的交易函式。不得由前端自填擁有者、班級、計次或最終報告。

## 教師權限規劃

| 角色 | 可以做什麼 |
| --- | --- |
| 學生 | 讀自己的基本資料、追蹤清單與施測歷程 |
| 輔導教師 | 讀被授權上課組別的學生資料與歷程；後續可寫自己的輔導備註 |
| 管理教師 | 依學校範圍管理名單、停用／重設學生帳號；另行授予匯出或教師管理權限 |

教師須由專案管理者指定；不因知道某個網址、填入某個電子郵件或修改前端欄位而獲得教師權限。教師使用獨立帳號，依使用者指定建立憑證。實際授權存在 `teacher_access`，不依賴可自行修改的 user_metadata。

教師後台入口 `/teacher/` 已開放，首頁頁尾亦有連結。已依使用者明確指示建立一位教師：本校所有上課班級的資料讀取權限，不含帳號管理、匯出或刪除。可依姓名／學號搜尋、分別篩選上課班級與原班級，點「查看成果」讀取該生追蹤校系、探索完成次數、各階段成果、逐題作答與學科自評。備註操作尚未開放。

教師登入透過 Auth 驗證，再讀取 RLS 保護的教師授權資料列，未授權或停用者不能載入名單。教師與學生的分頁工作階段分開保存；登出清空畫面與搜尋資料，切回背景分頁時會重新核對權限。建立帳號透過伺服器端 Auth Admin API 與具有獨立用途前綴、限時單次的管理授權，不將密碼、教師帳號或管理金鑰放入原始碼。

名單已擴充為 231 位（G10 81、G11 77、G12 73）。介面採雙欄：左側篩選及選擇學生，右側直接顯示追蹤清單與探索成果，最近一次成果預設展開；不再另開彈出視窗。年級選單同時提供整個年級及原班級，與班別交叉篩選。G10 的 1001／1002／10A 在畫面標示為 1001主／1002主／10理A，資料庫原值與既有教師授權規則維持不變。結束登入改為右上角圖示。

## 下一階段實作順序

### 1. 追蹤清單同步

已完成。保留既有追蹤頁與最多 100 筆上限。新增／移除採操作 ID 與預期版本，以學生鎖定交易，保留移除時間；衝突回覆 409 並重載，避免舊分頁復活已移除項目。校系名稱、年度與管道由正式網站的精簡招生目錄核對，不採用前端任意文字。登入時讀取帳號清單；舊訪客清單須明確點選匯入。登出清空私人畫面、分頁草稿與私人佇列，保留原來的訪客紀錄。

### 2. 個人施測歷程

已完成。全新開始建立 attempt。完成基本流程保存 quick；補答新題保存 extra 與批次；完成深入探索保存 deep；修改已完成的答案保存 revision。先前結果不覆蓋，每筆保存實際題號、逐題答案、學科自評、題庫與計分版本及後端重新計分的報告。同 attempt 的相同內容雜湊只保存一次。

後端打包與網站一致的題庫與引擎，拒絕非目前版本、變造或未完成的答案。現在「重新測驗」會合併新舊答案，屬同一 attempt 的補充階段，不當作獨立重測信度樣本。每人每日最多新建 30 個 attempt，每 attempt 最多 200 筆成果，避免重複或異常請求。研究用途與資料保存期間仍需另訂；登入提示已說明供授權教師輔導使用。

學生未登入時繼續使用原來的 localStorage；登入後草稿限於 sessionStorage 並以帳號區隔，已完成成果存資料庫。再次登入可恢復最近一份成果；舊訪客成果需自行點選匯入，來源記為 browser_import，時間顯示為匯入儲存時間。尚未同步時顯示失敗與重試，不能宣稱已儲存。

正式服務驗證使用獨立 verification 學校下的虛構帳號，確認四階段歷程、同份成果去重、清單版本衝突、同校教師可讀及跨學生／跨校拒絕。亦從正式網頁完成追蹤與探索，確認教師可查看。驗證完成後刪除全部測試資料與 Auth 帳號，停用臨時驗證端點；正式 81 位學生與 1 位教師保持不變，未將虛構作答寫入實際學生紀錄。

### 3. 教師後台

班級名單、篩選、搜尋、學生詳細頁、目前追蹤校系與歷次成果均已完成。成果每頁載入 100 筆，可繼續載入更早成果；完成次數以 distinct attempt 計算，補充與深入階段不增加次數。後續再增加教師私人備註、約定行動與下次追蹤日期。

### 4. 管理與匯出

受控匯入名單、更新班級、重設或停用帳號、撤銷教師權限；匯出依班級、日期與類型限縮範圍，記錄操作者及時間。CSV 避免公式注入並保留學號文字。學生可見範圍由資料庫執行，後台不先下載整校資料再靠畫面隱藏。

## 部署與後續維護

- DDL 來源在 `supabase/migrations/`，登入函式來源在 `supabase/functions/student-access/`。
- 初次 schema 透過已登入的管理頁 SQL Editor 執行；不要重複執行建表腳本。若未來改用 CLI migration，先為既有 schema 設定基準，避免重複建表。
- 名單匯入透過受控 Edge Function，需事先建立限時、單次的私有匯入授權。其 token 不進網站設定、原始碼、網址或公開紀錄。匯入不重設既有學生密碼。
- 免費方案需留意服務暫停、用量與備份政策。正式教學前先用少量帳號驗證，再安排整班使用；一般訪客不依賴登入服務。
- 權限／資料同步、教師後台等後續功能，每一項完成驗收才開放，介面不得宣稱已保存尚未同步的資料。

## 2026-10-29 連線後複查

Supabase 管理連線確認專案為 ACTIVE_HEALTHY，81 位學生資料均在，所有 8 張公用／私人資料表皆啟用 RLS。已撤銷平台自動建立的 `rls_auto_enable()` 對 PUBLIC、anon、authenticated 的直接執行權限；自動開啟 RLS 的事件觸發器仍啟用。另補上輔導紀錄 `teacher_id` 外鍵索引。

診斷剩餘項目：私人登入限制／匯入授權表故意不設一般使用者政策，代表預設拒絕；尚未有資料的歷程索引保留供未來功能使用。[密碼外洩檢查](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) 尚未啟用，官方目前僅於 Pro 以上方案提供；本次未升級方案或更動使用者指定的學號預設密碼方式。管理函式的權限警告與缺少外鍵索引提示已消除。
